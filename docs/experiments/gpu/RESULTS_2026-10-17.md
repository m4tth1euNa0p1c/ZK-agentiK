# CUDA RISC Zero 3.0.6: blocked result, October 17, 2026

**No GPU receipt was produced.** The GPU is accessible from Docker, but
compilation of the recursive kernel `kernels/cuda/step_exec.cu` fails with
an OOM stop under the **12 GiB** limit, first with four Cargo jobs, then one.
This local result demonstrates neither Blackwell incompatibility nor the
impossibility of compiling with a different memory budget or configuration.
No global Docker or driver change was made and no paid service was called.

## Resume without turning a failure into a success

```bash
node scripts/risc0-gpu-lab.mjs critical 1
# Or reuse the retained container's caches:
node scripts/risc0-gpu-lab.mjs critical 1 zk-agentik-risc0-gpu-2026-10-17t14-34-50-644z-231fa047
```

The runner retains its one-job and 12 GiB defaults; repeating identical
parameters may reproduce this blocker. A later experiment should explicitly
change a single variable, for example the build budget in an environment
that actually has that memory, or a documented compilation parameter, and
retain this new profile separately. This remains a resolution hypothesis,
with no request for a global system change and no additional trial launched here.

If compilation succeeds, the runner must observe failure of an **actual
`Succinct` attempt for the same guest with `CUDA_VISIBLE_DEVICES=-1`**, then
generate with the GPU visible, compare the historical ELF and verify the
receipt in a public-only CPU container without network access.
A mere `nvidia-smi`, version or label cannot satisfy these criteria.

The requested profile combines a `Succinct` STARK receipt with Ed25519
signatures and a public fixture authority. It **is not post-quantum end to end**,
authenticates no real supplier, and this blocker provides no new conclusion
about its confidentiality.
