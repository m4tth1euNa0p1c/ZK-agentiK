**La campagne de 4 096 vecteurs passe sous Windows et sous GitHub Linux. MATLAB
R2026b, Octave, BigInt et le code Rust concordent sur les mêmes valeurs.**

de plateforme bancaire. Les dates sont issues des horloges d'exécution, sans TSA.

Une divergence intéressante est documentée dans les autotests : les divisions
natives `idivide` testées aux maxima u32/u64 concordent avec le quotient attendu
dans MATLAB R2026b, mais pas dans Octave 7.3.0. L'oracle commun évite cette
opération pour les grands entiers et reconstruit le quotient exactement par
bits. Les chaînes décimales empêchent aussi la perte de précision au-delà de
`2^53`. Cette correction concerne l'oracle numérique, sans remplacer
l'arithmétique Ristretto ou une primitive cryptographique.

## Résultats négatifs conservés

Les premiers jobs Linux
[128 cas](https://github.com/m4tth1euNa0p1c/ZK-agentic/actions/runs/39052542612) et
[4 096 cas](https://github.com/m4tth1euNa0p1c/ZK-agentic/actions/runs/39052615109)
au commit `e7fc348` ont échoué à l'étape `octave-self-tests`, code 1.
Ils ne sont pas comptés comme campagnes corrélées réussies. Leurs bundles
[court](runs/gha-39052542612-failed/manifest.json) et
[étendu](runs/gha-39052615109-failed/manifest.json) conservent les sorties Rust
et les fichiers manquants explicitement signalés ; MATLAB n'avait pas été lancé.

Le diagnostic de permissions a été reproduit avec un volume Linux éphémère :
un dossier 0755 appartenant à UID 1001 refuse l'écriture à root privé de
`CAP_DAC_OVERRIDE`, puis accepte UID 1001. Les
[observations de ce probe](checks/linux-bind-mount.json) et la réussite des
nouveaux jobs soutiennent le correctif `581dbeb`. Le runner transmet UID:GID
de l'hôte sous Linux, garde le réseau désactivé, le système en lecture seule,
les capacités retirées et un `/tmp` éphémère. Il n'ajoute ni chmod global,
ni secret, ni capacité. Docker rootless/user namespaces restent non qualifiés.

## Démonstration, revue et limites

Les [contrôles locaux](checks/local-validation.json) couvrent Rust fmt/Clippy,
tests des workspaces, TypeScript, Horizon, SDK, schémas et guest. Huit tests du
banc vérifient notamment l'omission, les doublons, les faux statuts de réussite,
les mauvais motifs de refus et les corpus substitués. Quatre tests Rust du
binaire de campagne couvrent les preuves réelles et le contournement du preflight.
La [CI qualité](https://github.com/m4tth1euNa0p1c/ZK-agentic/actions/runs/39053037533)
et la [CI de publication](https://github.com/m4tth1euNa0p1c/ZK-agentic/actions/runs/39053037539)
sont réussies sur `581dbeb`.

La [démonstration d'autorisation](checks/agentic-demo.json) produit une preuve
réelle et un seul effet SQLite synthétique ; falsification, rejeu et baisse
de confidentialité sont refusés. Les scénarios MCP/stdio passent séparément
dans `test:horizon`. Le [profil Proofkit](checks/proofkit-profile.json) exécute
effectivement la campagne courte. Le [rapport HTML](checks/browser.json) a été
ouvert dans Chrome headless avec un profil isolé ; son script a rendu les
compteurs, lignes et catégories. Aucun audit d'accessibilité complet n'est revendiqué.

La [revue contradictoire](REVIEW.md) a fait corriger les contrôles de provenance,
de complétude et d'erreur native. La contre-revue du correctif Linux a vérifié
le maintien des restrictions ; les hashes des 13 fichiers du bundle Windows,
des deux entrées, des deux renderers et des six sorties de la vue concordent.
Ces revues sont internes à l'équipe d'agents, pas un audit cryptographique externe.

Le [supplément PDF](../../whitepaper/circuit-validation.pdf) contient cinq pages
de démonstration conditionnelle et de méthode ; il a été compilé sans warning
ou débordement et ses pages inspectées. GitHub reconstruit désormais ce
supplément avec le manuscrit principal dans le profil `math`.

Les durées brutes sont celles d'une campagne de correction, pas d'un benchmark
avec échauffement ou isolation de charge. Aucun SLA, avantage GPU, record Vega,
profil post-quantique ou preuve formelle machine de l'implémentation n'est établi.
La vérification utilise la même bibliothèque verrouillée dans un processus
séparé ; elle ne prouve pas la vérité des autorités, la confidentialité des
métadonnées ou l'atomicité d'une API distante. H11/H13/H14/H15/H17 restent ouverts.
